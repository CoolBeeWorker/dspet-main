# DSPET 1.0 —— 住在 Windows 3.0 桌面上的 DeepSeek 鲸鱼娘

> 一个真正的 16 位 Windows 3.0 程序(或许也有DOS版？）。一个蓝头发的Deepseek鲸鱼娘站在你的桌面角落一动一动散步，被你冷落一会儿就睡着，说话走 PC 喇叭——不需要声卡，但或许也可以有声卡？为 Intel 386/20、2 MB 内存的机器而写。

现在这里有**两个**程序，共用同一份美术和同一份语音：

| 程序 | 用途 |
| --- | --- |
| `DSPET.EXE` | Windows 版——透明地站在桌面上 |
| `DSPDOS.EXE` | DOS 版——全屏运行，不需要 Windows |

![角色总览](art/all_frames.png)

---

## 这是什么

程序启动后，她会出现在桌面右下角附近，站在那儿。左键拖走、左键单击让她打招呼、右键弹出一个八项小菜单。桌面是你自己的，她只是浮在上面，除了她自己那 72×56 个像素，其余地方一个点都不改。

她不是内存大户：整个精灵库约 19 KB 全局内存，语音库 53 KB，装在 2 MB 的机器上不碍事。启动时把桌面她脚下那块拍下来存在内存里，每次移动先把她自己的像素抹掉、再把桌面还回去——1991 年的老办法，跑在 386 上够快。

## 她是怎么画出来的

全部是手摆的像素，72 × 56 点，十六色，一像素黑色描边。这个尺寸下只有最强的特征能活下来，所以设计时严格保留这几样：

- 白色荷叶边女仆头饰，戴在头**后面**，于是表现为头发周围一圈锯齿状的蕾丝光晕
- 深藏青长发，顺着头发的长度变亮，到发梢几乎漂成淡蓝
- 大蓝眼，一点白色高光（看着有点不如新版，但确实RETRO）；刘海带尖齿，从齿缝里透出额头
- 藏青女仆裙，白围裙上绣着一只小鲸鱼，腰带上有金色铆钉，颈间一枚带宝石的蓝蝴蝶结
- 鲸鱼尾鳍戴在耳后，鲸尾的两瓣在裙后向上卷起

在 72 × 56 下必然丢掉、因此被简化掉的：蕾丝织纹、袖口的金线绣、荷叶袖口、单缕头发准确的波浪形状。

## 1.0 新增：多种显示模式，以及一个 DOS 版本

这一版要解决的是「更多显示模式」和「也能在 DOS 下跑」。这两件事其实是同一个问题的两面，因为 Windows 和 DOS 对「谁拥有屏幕」的答案是相反的。

### Windows 侧：应用不能改视频模式

在 Windows 里，**应用程序是无法改变视频模式的**。只有显示驱动能改，而驱动是在 SETUP 里就选定好的，程序跑起来时木已成舟。Windows 程序能做的只有三件事：查清自己被分到了什么、按那个色深正确作画、并且把它说出来。1.0 做的就是这三件：

**（1）渲染档位从三档变四档**，`Menu > Sprite look` 循环切换，选择写进 `DSPET.INI`：

| 档位 | 说明 |
| --- | --- |
| `colour` | 十六色原图 |
| `mono` | 程序自己生成的一比特版本，带 4×4 有序抖动 |
| `mono inverted` | 同上，黑白互换 |
| `mono solid` | 一比特硬阈值，不抖动 |

第四档是给 640×480、像素颗粒又粗的 LCD 准备的。在这个点距上，抖动看起来不像明暗过渡，只像脏点——所以干脆阈值切干净。

**（2）精灵调色板吸附到设备真实拥有的颜色上。** 十六色驱动上映射本来就是精确的；但在 256 色驱动上，同样这十六个颜色可能整体错开一格，于是皮肤和头发糊成一片。

**（3）`Menu > Display info`** 报告 `SYSTEM.INI` 里的驱动文件名、分辨率、色深、调色板项数、设备是否支持位块传送，以及当前用的是哪一档。

### DOS 侧：程序自己挑模式

DOS 下没有窗口管理器、没有调色板管理器、也没有驱动可问，所以程序**自己**通过 BIOS 选视频模式，用自己的 blitter 画。支持八种：

| BIOS 模式 | 分辨率 | 颜色 | 显存布局 |
| --- | --- | --- | --- |
| `12h` | 640×480 | 16 | 四平面 |
| `11h` | 640×480 | 2 | 四平面全开 |
| `10h` | 640×350 | 16 | 四平面 |
| `0Fh` | 640×350 | 2 | 四平面全开 |
| `13h` | 320×200 | 256 | 线性，1 字节/像素 |
| `0Dh` | 320×200 | 16 | 四平面 |
| `06h` | 640×200 | 2 | CGA，1 bpp，B800 分两页 |
| `04h` | 320×200 | 4 | CGA，2 bpp |

启动时挑你的 BIOS 接受的最好一档，`Menu > Display mode` 往下轮。`Menu > Check display modes` 把八个全试一遍，告诉你这台机器**真正**有哪几个——判据只有一个：调用 `INT 10h AH=00h` 之后读 `0040:0049` 的模式字节，它如果没变成你要的值，就是 BIOS 拒绝了。**BIOS 永远返回「成功」，所以除了这个字节，没有别的诚实测试。**

![八种模式下的同一帧](art/dos_v10.png)

DOS 版有两样东西是从机器上要的，不是我能给的：

- **鼠标驱动。** 它只跟 `INT 33h` 打交道，别的都不会。所以 `MOUSE.COM`（或 `CONFIG.SYS` 里的 `DEVICE=MOUSE.SYS`）没加载，就根本没有箭头。此时键盘接管一切：方向键移动高亮、Enter 选择、Esc 关闭、空格让她说话、`M` 开菜单、`F1` 是「关于」。
- **装得下所选模式的显示器。** 在 L40 SX 上，面板是 640×480 单色，后面的适配器是普通 VGA，所以 `12h`（640×480，16 色）才是用满每一个像素的模式。那十六个颜色送到单色面板上，被属性控制器翻译成十六级灰——这就是她在上面看着「发软」的原因。`11h` 是干脆的一比特替代品，一次菜单点击就到，或者一条命令：

  ```
  DSPDOS 11
  ```

  320×200 的几个模式是为完整性留着的。640×480 面板会把它们拉伸，看起来粗糙——能用，不好看。

### 两个版本故意保持一致的地方

同一份 `DSPET.SPR`、同一份 `VOICE.DAT`、同一套步态节奏、同一个睡眠计时、同一套菜单文案。行为不一致的两个构建，等于两个要调试的程序。

## 0.9 新增：双色屏

那台调试用的机器是黑白显示器，而且是反色显示的。就这一个事实，解释了前四个版本里所有活下来的画面故障。

当时发生的事：角色是十六色美术，而 blitter 把这些彩色位图交给了一个**只有两种颜色**的驱动，而且是在一次光栅操作的正中间（掩膜用 `SRCAND`，颜色用 `SRCPAINT`）。在 OR 里把彩色转成黑白，是这个 API 里那些当年小驱动从来没正确实现过的角落——每个驱动都在即兴发挥，而即兴发挥落在**位模式**上，不落在颜色上。当时看到的就是灾难现场：角色大部分不在，以及某个半字节碰巧对齐时出现的一道黑色圆弧。

0.9 不再要求驱动做这件事。

- 启动时从屏幕读 `NUMCOLORS` 和 `BITSPIXEL * PLANES`。两色意味着单色驱动，于是精灵库**由本程序自己**根据文件里的调色板在这里构建。
- 亮度分成三段：110 以下纯黑，185 以上纯白，中间走 4×4 有序抖动。单纯阈值会切出一张没有五官的纸人；全范围抖动会把头发变成彩纸屑，角色淹死在自己的噪点里。两个分界点是拿真实精灵库过一遍 `tools/mono.py` 看图定下来的，不是凭口味。
- 每一次 blit 都是一比特对一比特，没有留给驱动解释的余地。
- 极性跟随刚刚拍下来的桌面。浅色桌面就照原样画——深色头发、深色描边；深色桌面则取反。那台机器的桌面是浅的，所以她走前一条；又因为显示器反显，她那团黑发和黑描边到玻璃上变成**白色**。于是在那块屏幕上，她是黑桌面上一个白影，这已经是两色能做到的最好读法。

菜单项 `Sprite look` 循环切换这几种渲染，选中即重画：

```
colour         十六色原图
mono           程序自己的一比特版本
mono inverted  同上，黑白互换
```

选择写在 EXE 旁边的 `DSPET.INI` 里，重启还在。

**一个在单色面板上很要紧的提醒。** 自动判断读的是**驱动**，而驱动看不见显示器。8543-A44 是 L40 SX：一块单色 STN 面板，由一块彩色 VGA 控制器（WD90C20）驱动。Windows 加载的是普通十六色 VGA 驱动，驱动如实地报告「十六色」，面板自己把它们变成灰阶。所以程序选 `colour` 并不能算错——它只是无法知道面板把这些颜色怎么了。如果你要的是两端极性而不是灰阶，就手动选 `mono`；这是唯一的办法，因为面板没法问。

命令行（用于实验，优先级高于已保存的选择）：

```
DSPET MONO     以 mono 启动
DSPET COLOR    以 colour 启动
DSPET INVERT   以反色 mono 启动
```

日志开头现在是这样一行：

```
gfx: 640x480 colours=16 bpp=4 driver=colour look=mono
```

它把「驱动怎么回答的」和「实际用了哪一档」记在一起。

## 版本记录

### 0.8

四个故障，其中第四个是前三个为什么这么难看出来的原因。

1. **「现在每个菜单项都会让程序退出。」**
   硬件检查和「关于」框都正常显示了（日志里有 `box closed`），然后程序在一毫秒后死掉。这两个功能在框关闭后都调用了同一个函数，「四处走走」也调它，普通启动三秒后的自动散步还调它——这正是某几份日志里有些运行只剩一行 `run starts` 的原因。
   那个函数是 0.5 加入、0.7 扩展的「重新抓取桌面」例程。**它已经删了。** 它隐藏窗口、泵消息队列、对底下任意窗口调 `InvalidateRect` 和 `UpdateWindow`、拍屏、再把窗口显示回来。这种强度的东西不该出现在一个 55 ms 的定时器处理里。留下来的是 1991 年的算法，够用：`PutBg` 把保存的桌面写回帧缓冲，`GrabBg` 读回来，而在那个瞬间角色可证明不在帧缓冲里。两个消息框现在只是重画。

2. **「走路时她变透明，只剩一团半透明的影子拖着一个窗口图像在抖。」**
   那是**两个**角色长得像什么。每个角色都会拍屏去了解自己背后是什么——于是各自拍到了**对方**，然后把那些像素每帧画回来。两个角色还会同时写这个日志文件，而 `OpenFile` 拒绝第二个写者，这就是日志丢行、以及两行交错成乱码的原因。
   0.1 里的重复实例检查是照教科书写的：`if (hPrevInstance) { 已在运行 }`。在 Windows 3.x 里 `hPrevInstance` **永远是 0**，所以那个分支从来没执行过，你启动的每一份都活着。现在改用 `FindWindow`，有效。启动第二份会把已在跑的那份提到前面然后自己退出，绝不增加第二个角色。

3. **「保存的背景被污染了。」**
   这条是用模拟验证的，不是靠辩论：把 `PutBg / GrabBg / composite / blit` 这个精确序列在一块合成桌面上重放 220 个一像素步进，保存的那份副本里**零个**错误像素。把 `PutBg` 那一步去掉再重放，4032 个像素里污染 2644 个。`PutBg` 不是家务活，它是让「拍照」这件事诚实的原因，所以它还在。
   另外两处改动让 386 上的走路更便宜也更稳：
   - 窗口类不再带 `CS_HREDRAW | CS_VREDRAW`，`SetWindowPos` 传 `SWP_NOREDRAW`。USER 原来在每走一个像素时就把窗口的 4032 个像素整个重画一遍，叠在本程序已经做过的 blit 之上。那次重画没了。
   - 消息框关掉之后桌面副本依然有效（框从没往里面画），所以什么都不用重拍。

4. **新增：日志开始记录那些从外面根本无法区分的事情。**

   ```
   wnd: created at x,y          窗口真的存在，在哪儿
   wnd: 72x56 visible           而且可见
   walk: start dir=... ticks=   每一次散步，带方向
   walk: from x,y               从哪儿开始
   walk: end x,y                到哪儿结束
   wnd: was NOT visible ...     窗口丢了 WS_VISIBLE 又被显示回来
                                （每个 tick 都跑的自愈检查）
   wnd: WM_DESTROY              窗口真的被销毁了
   loop: message loop ended     程序真的退出了
   app: quit requested          是点了 Exit，也就是故意的
   ```

   于是下一份日志能回答「它是退出了，还是只是变隐身了」，不用猜。

### 0.7

三个故障：硬件检查（第三次尝试）、头旁边一道黑弧、一团拖着窗口碎片的半透明影子。

1. **硬件检查。** 收到的日志停在 `hw: build version text`，所以故障在那行之后的**第一个语句**——第一次调用 `Cat()`。这一下彻底排除了 `wsprintf`（它早就删了），只剩 `lstrcpyn` 是本程序里唯一从没活着跑完过的 KERNEL 调用：0.2、0.4、0.5、0.6 全都死在这个函数里。而与此同时，每一行日志每次运行都要在栈缓冲上几十次地调 `lstrcpy` 和 `lstrcat`，从来没出过事。
   所以 `Cat()` 现在一个 API 都不调，逐字节拷贝；那个把报告复制进消息框缓冲的 `lstrcpyn` 也以同样方式删掉了。这一段现在每个语句写一行日志，所以万一还失败，日志会指出是哪个语句，而不只是哪个函数。

2. **头旁边那道黑弧。** 鲸鱼尾鳍原来画成比它上面的深蓝形状稍大一圈的黑色块，用来做边。头发被画在它们内侧的一半之上，于是发梢处活下来的只有那道黑边本身——几个孤立的黑像素，旁边没有任何颜色，在屏幕上看就是浮在头旁边的一道弧。黑色衬底删了；全局的一像素描边那一遍本来就会画边，而且永远贴着颜色。

3. **走路时拖着窗口图像的半透明影子。** 她背后的桌面副本是在「她刚露出来的那个窗口还没重画」的时候拍的。`ShowWindow(SW_HIDE)` 只是把那一块标记为无效，真正的绘制要等那个窗口收到 `WM_PAINT`，而在一个闲置桌面上这个消息可能永远不被派发。于是相机拍到了仍然属于她的像素，或者几毫秒前还在上面的某个窗口的像素。这些像素此后每一帧都被画回来，而每一次新的抓取又把脏副本再复制一遍——一道永远不会自己愈合的涂抹。现在在开相机之前，先把底下那个窗口同步地作废并立即重画；副本在每次散步开始时刷新，闲置时也刷新。

### 0.6

一个故障：「硬件检查现在直接弄死程序，连错误框都没有。以前它至少先卡一下。」

收到的日志停在 `hw: GetVersion`，所以故障就在紧接着的语句——用 `wsprintf` 拼版本那一行。

原因：在 16 位 Windows 里，USER 的 `wsprintf` 中的 `%s` 转换取的是**近指针**。它只拿 16 位偏移量，然后通过**调用者**的 DS 去读，而本程序的 DS 是 DGROUP。但这个程序的栈是它自己的段——NE 头里写着 `SS:SP = 23A2:0001`，而 DGROUP 是段 2 且总共只有约 6 KB——所以一个栈缓冲的偏移量当作 `DS:offset` 用，就指到了段尾之外。保护模式下这就是保护性异常：没有错误框，程序直接消失。这正是当时看到的现象。

0.4 用的是 `%Fs`，意思是「远指针」，那是对的，所以 0.4 死得晚一些（一路走到堆压缩）。0.5 把它「简化」成近指针转换，把故障往前挪了。这是我的错。

修法不是换一个格式字母：**`wsprintf` 已经从程序里彻底移除。** 所有字符串用 `lstrcpy` / `lstrcat` 拼（它们取远指针、保留段），数字过一个十二行的十进制转换器。已验证：源码里不再有任何 `%s` 或 `%Fs` 转换，也没有任何一次 `wsprintf` 调用。

另一处用过 `wsprintf` 的地方（`start: transparent 640x480 voice=on` 那行）之所以活着，只是因为它的参数是放在 DGROUP 低偏移处的字符串字面量——那是运气，不是正确——也一并改掉了。

硬件报告现在在每个 API 调用前后都记进入和退出，所以万一还出问题，`DSPET.LOG` 的最后一行会指出语句；并且报告在消息框弹出**之前**就已经写进日志。

### 0.5

报告上来的三个故障，以及它们各自真正是什么。

1. **「硬件检查还是终止，但先卡了一下。」**
   卡的是 `GlobalCompact(0L)`。那不是查询——它整理整个全局堆，在 2 MB 的机器上就是一段看得见的停顿。改成 `GlobalCompact(-1L)`，只报告。
   同一条路径还对**显示驱动**模块调了 `GetModuleFileName`，而驱动句柄不保证能活过这个调用，那个调用删了。报告现在只用 `GetWinFlags` / `GetVersion` / `GetDeviceCaps` / `WIN.INI` 构建。它也同时写进 `DSPET.LOG`，所以即使框死了，这份报告也还在。
   现在每一次单独的 API 调用都在**执行之前**先往 `DSPET.LOG` 写一行，所以万一还是死，那文件的最后一行就点了名。

2. **「她说话的时候大半个身子不见了。」**
   对口型的脏矩形是 26..46 × 28..40 —— 20×12 个像素，盖住了下巴、脖子、领口和围裙胸襟，不只是嘴。整块每秒被重写约三十次，每次重写是两次 blit（掩膜用 `SRCAND`，颜色用 `SRCPAINT`）。这两次之间，目标区域是一个黑色剪影；一赫兹的时候没人看得见，三十赫兹的时候眼睛就读成「她那部分没了」。两处改动：
   - 矩形现在是 33..39 × 25..30，嘴加一个像素的余量（嘴戳在 35,27，最大 3×3）
   - 每次更新先在屏外合成为一张图，再用**一次** blit 上屏，于是中间那个黑色状态根本不存在

   三个说话帧在这个框之外现在也是逐字节相同的——这才让局部重画成立。

3. **「她动得太快，看不清。」**
   原来每个 55 ms 的 tick 走**两个**像素——36 px/s，把擦除/移动/重画的循环翻了一倍，也让她底下桌面的重画达到每秒 18 次。现在一个 tick 一个像素，18 px/s，腿部循环四拍一换而不是两拍。窗口也不再为每次移动而作废：成品图直接 blit 上去。

0.5 还做了这些：

- 点她让她说话，不再在鼠标处理函数里直接播放语音。它投递一个消息，由主循环播放，和菜单一样。在窗口过程里阻塞，就是弄死 0.2 的那个错误。
- 两个对话框现在都是无主的。角色窗口是个从未获得过焦点的 `WS_EX_TOOLWINDOW` 弹出窗口，对这样一个窗口做 `MessageBox` 的禁用/恢复，在 3.0 上是已知的「不可恢复应用程序错误」制造法。
- 桌面副本能正确刷新了：拍照期间把窗口隐藏起来。旧的「先擦后拍」两步永远拍不到变化，因为它先把旧副本写了回去。
- `DSPET.LOG` 有大小上限，并且每次运行以一行标记开头。

### 0.4

- 角色按参考插图重画。脸、头饰、头发轮廓全部重建；眼睛改用像素图绘制，不再用叠起来的椭圆
- 皮肤现在有自己的调色板项。0.3 里面部、围裙、头饰都用纯白，于是糊成一整块
- 侧鳍改画在头发**后面**，原来是画在前面，所以看起来像一对翅膀
- 不再像戴了头盔：长发顺直垂下，不再比头还宽地支棱开
- 裙子提高、鞋改了颜色，所以她走路时看得见腿

### 0.3

- 她会走路了：闲置时自己挑个方向，散步几秒，碰到屏幕边缘反弹，然后歇着
- 右键菜单不再弄死程序。原来的菜单在自己的消息处理函数里销毁自己的窗口，那就是「不可恢复应用程序错误」的来源
- 「硬件检查」不再写任何 I/O 端口。从 Windows 程序里去探测不存在的 COM/LPT 地址并不安全，那是那次崩溃的另一半；现在改为问 Windows 和 `WIN.INI`
- 语音库原来 71800 字节，超过加载器能接受的 60000，所以它从来没被真正加载过，「打个招呼」一直是无声的。现在 6 kHz / 53857 字节，真的会响
- 每个菜单命令都先往 `DSPET.LOG` 写一行，所以崩溃可以追到具体是哪条命令

## 现在能做什么

**已可用**：角色、透明、拖动、走路、闲置/睡眠、口型同步、七句固定语音、硬件报告、四档渲染、显示信息报告，以及一个有八种视频模式的完整 DOS 构建。

## 盘上的文件

| 文件 | 字节 | 校验和 |
| --- | ---: | --- |
| `DSPET.EXE` | 19984 | `4271` |
| `DSPDOS.EXE` | 24870 | `CABC` |
| `DSPET.SPR` | 36052 | `CECD` |
| `VOICE.DAT` | 53857 | `0054` |
| `JOIN.EXE` | 19238 | `120B` |
| `CRC.EXE` | 17668 | `D67A` |
| `README.TXT` | 28685 | `A145` |

总计 200354 字节，一张 1.44 MB 软盘（实际可用约 1.30 MB）绰绰有余，所以这一版不需要 `JOIN` 切分。`JOIN.EXE` 仍然留在盘上，是给将来文件变大时用的：那时大文件会被切成 `XXX.001`、`XXX.002`……，`JOIN` 按 `JOIN.LST` 把它们拼回去并打印尺寸和校验和。

## 运行方法

### Windows 版

1. 把盘插进 A: 驱。
2. 拷到硬盘。在 DOS 提示符下：
   ```
   C:
   MD \DSPET
   CD \DSPET
   COPY A:*.*
   ```
3. 输入 `WIN` 回车，启动 Windows。
4. 在程序管理器里选 `文件 > 运行`，输入：
   ```
   C:\DSPET\DSPET.EXE
   ```
5. 鲸鱼娘出现在桌面右下角附近。

### DOS 版

1. 先确认鼠标驱动已加载：提示符下敲 `MOUSE` 回车，或在 `CONFIG.SYS` 里加 `DEVICE=MOUSE.SYS`。
2. 进到程序目录，直接运行：
   ```
   CD \DSPET
   DSPDOS
   ```
   命令行参数（都可省略）：
   ```
   DSPDOS 12      指定 BIOS 视频模式，十六进制写法，12 就是 640x480x16
   DSPDOS 11      640x480 两色，单色面板上最干脆的一档
   DSPDOS /I      角色反色（黑桌面上用白影）
   DSPDOS /N      关掉抖动，硬阈值切干净（等于 mono solid）
   ```
3. 屏幕切到图形模式，出现白桌面、黑字菜单和她。**退出按 Esc**——Ctrl-C 被刻意拦掉了，因为在图形模式下中断出去会留下一个看不见的提示符。
4. `DSPDOS.LOG` 写在 EXE 旁边，记录它要了哪个模式、实际拿到哪个、美术和语音库有没有加载成功。

## 出问题怎么办

### A) 弹出「无法加载精灵库」

这个框现在会列出它试过的每一条路径，并给出原因码。读消息末尾的数字：

| 码 | 含义 | 怎么办 |
| --- | --- | --- |
| 1 | 没有这个文件 | `DSPET.SPR` 真的不在那条路径上。用 `DIR DSPET.SPR` 确认文件在、名字没被缩写（比如 `DSPET~1.SPR`，那说明它是从一张长文件名被破坏的盘上拷来的） |
| 2 | 文件损坏或过短 | 传输中被截断。重拷，再跑一次 `CRC` |
| 3 | 头部/尺寸不匹配 | 这个 SPR 和这个 EXE 不是同一版本，或被改过。两个一起重拷——它们必须来自同一张盘 |
| 4 | 内存不足 | 关掉其他程序；精灵库需要约 19 KB 全局内存 |
| 5 | GDI 拒绝 | 显示驱动不肯创建位图。把硬件检查里的分辨率和驱动名记下来，贴到 issue 里 |

程序也会搜索 `C:\DSPET\DSPET.SPR` 和当前目录，所以工作目录不对不再致命。

### B) 什么都不出现，或者 Windows 说它不能运行这个程序

把 `CRC.EXE` 也拷到硬盘，然后敲：

```
CRC DSPET.EXE DSPET.SPR VOICE.DAT
```

把打出来的数字和上面的表对比。对上了，说明文件完好无损地到了，问题在别处。

### C) 她出现了，但一点声音都没有

PC 喇叭这条路直接对 `61h` / `42h` / `43h` 端口做 I/O。在「386 增强模式」下有些机器会拦这个。试试标准模式启动 Windows：`WIN /S`，然后重跑 DSPET 点她。如果在那里能响，原因就是这个，我再加一条回退路径。

### D) 她身后拖着一串旧画面，或者她底下的桌面看着不对，有别的程序在往上画

用这个开关启动：`C:\DSPET\DSPET.EXE -solid`。它关掉透视把戏，在她身后画一个纯灰方块。这样就能判断是不是「抓取/恢复」那段代码的问题。

### E) 弹出「不可恢复应用程序错误」

打开 `DSPET.LOG`（就在 `DSPET.EXE` 旁边，纯文本），看**最后一行**。每个菜单命令都在执行前先写日志，所以最后一行指明了死掉的具体操作——比如 `cmd: say hello` 或 `cmd: hwcheck, building report`。把那一行贴到 issue 里，我就能指到代码。

### F) 角色看不清，或者看着像一堆散点

右键选一两次 `精灵渲染`。它在 colour → mono → mono inverted → mono solid 之间循环，四档里总有一档是干净的人形。不用重启，选择会记住。不管你最后停在哪一档，把 `DSPET.LOG` 里的 `gfx:` 那一行贴到 issue 里——它记着驱动怎么报的、实际画了什么。

### G) DOS 版起来了但画面不对，或者停在「这台机器没有一个可用的图形模式」

`DSPDOS.EXE` 旁边的 `DSPDOS.LOG` 记录了它要的模式、拿到的模式、美术和语音库有没有加载成功。把这个文件贴到 issue 里。同时把 `Menu > Check display modes` 的结果也贴上：它列出全部八个模式，并说明这个 BIOS 接受哪些。

### H) DOS 菜单里的字看不清

DOS 版用 BIOS 通过 `INT 1Fh` 指向的 8×8 字库画字，这个向量从 1981 年起每一台 PC 的 BIOS 都会设置。万一某台机器指向了别处，菜单会像噪点，而角色本身画得没问题——那是 DOS 版里唯一一处取自 BIOS 而不是取自本程序的东西。

## 从源码构建

需要 **Open Watcom 2.0**。`WATCOM` 指向安装根目录，`%WATCOM%\binnt64` 必须在 `PATH` 上——那是 `wlink` 找 `wlink.lnk` 的地方，少了它每次链接都会报 `undefined system name: windows`。

```bat
set WATCOM=C:\WATCOM
set PATH=%WATCOM%\binnt64;%WATCOM%\binw;%PATH%
set INCLUDE=%WATCOM%\h;%WATCOM%\h\win
set LIB=%WATCOM%\lib286;%WATCOM%\lib286\win

build.bat
```

`build.bat` 分四步：编译并链接 Windows 版 `dist\DSPET.exe`；编译并链接 DOS 版 `dist\DSPDOS.exe`（链接脚本 `build\dspdos.lnk` 不存在时自动生成，栈 8 KB）；再编译两个 DOS 小工具 `JOIN` 和 `CRC`。编译开关是 `-ml`（大内存模型）`-os`（优化尺寸）`-3`（386），Windows 目标额外加 `-bt=windows`，DOS 目标是 `-bt=dos`。

再做一张盘：

```bat
python tools\mkfloppy.py G:\
```

它按 1.30 MB 的实际可用容量检查体积，必要时自动切分大文件并生成 `JOIN.LST`，然后重算每个文件的校验和，用这些数字**生成** `README.TXT` 里那张表——所以表和文件永远不会对不上。

### 工具

| 脚本 | 作用 |
| --- | --- |
| `tools/genart.py` | 画角色，导出 17 帧 PNG 与 `DSPET.SPR` |
| `tools/dump.py` | 把某一帧打印成字符图，用来逐像素核对 |
| `tools/mono.py` | 用真实 `DSPET.SPR` 预演 `spr.c` 里的单色构建 |
| `tools/mkvoice.py` | 把录好的 WAV 合成 `VOICE.DAT`（6 kHz、8 位无符号、无逐句头） |
| `tools/vidtest.py` | 用 Python 复刻 `vid.c` 的写入算术，把八个模式的位序、平面、分页解码回像素比对 |
| `tools/necheck.py` | 检查产物确实是 16 位 Windows NE 可执行文件 |
| `tools/mkfloppy.py` | 组装软盘内容、切分、算校验和、生成 `README.TXT` |

`vidtest.py` 在没有 DOS 环境时是唯一能发现位序和平面错误的手段——1.0 里它有四个真 bug 是靠它抓出来的：掩码方向写成了右移、CGA 的字节索引用了位移、每字节像素数算错、行宽只按 1 bpp 算。

## 反馈问题时请附上这些

`DSPET.LOG` 每次启动都会写在 EXE 旁边，纯文本，几行。把这个文件，连同硬件检查框里的文字一起贴到 issue 里，就能看出那台机器的样子。

DOS 版对应的是 `DSPDOS.LOG`，外加 `Menu > Check display modes` 打印的那八行。
